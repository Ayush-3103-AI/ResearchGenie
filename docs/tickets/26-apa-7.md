# APA 7: undated works and page ranges

Ticket for the Dev Agent (#26). Run it with:

```
researchgenie-dev --spec docs/tickets/26-apa-7.md
```

## Context

APA citations are rendered by `build_citation_map(paper_ids, metadata_by_paper_id, "apa-7")` in `services/research-writing/writing/modules/citation_formatter.py` (the `_apa` function, and the year-suffix logic in `build_citation_map`). Tests import it with `services/research-writing` on `sys.path`, as `tests/services/test_apa_citation_style.py` does, and build papers with `writing.schemas.PaperMetadata`.

## What to change

1. **Undated works by the same author.** Two papers by the same author(s) with `year=None` both render `(Zhou, n.d.)` today. APA 7 requires `(Zhou, n.d.-a)` and `(Zhou, n.d.-b)`, in the same order as the reference list (alphabetical by title), and the matching `Zhou, Z. (n.d.-a).` in each reference entry. A single undated work stays `(Zhou, n.d.)`.
2. **Page ranges use an en dash.** In an APA reference entry, a page range such as `121-133` must render as `121–133` (U+2013). Pages without a range (`e1234`) are unchanged.

Only `apa-7` changes. IEEE, Vancouver, Elsevier-Harvard, Chicago and MLA output must stay exactly the same, and every existing test must keep passing.

## Acceptance test

A new test file under `tests/services/` that fails before the patch and passes after it:

- two undated papers by "Zed Zhou" titled "Undated work" and "Undated work two" give `(Zhou, n.d.-a)` and `(Zhou, n.d.-b)`, and their reference entries contain `(n.d.-a).` and `(n.d.-b).`;
- one undated paper alone gives `(Zhou, n.d.)`;
- `citation_format_errors(citation, "apa-7")` is empty for all of them;
- an APA paper with `pages="121-133"` has `121–133` in its reference entry, and the same paper in `"ieee"` keeps `121-133`.

- Given 8 automated runs without converging, the fix was implemented directly instead of continuing the Dev Agent loop. The three shared validation regexes (`_AUTHOR_YEAR`, `_NARRATIVE_YEAR`, `_YEAR`) were widened to also accept the optional `-[a-z]` suffix, which is safe for the other styles since they never render it.
