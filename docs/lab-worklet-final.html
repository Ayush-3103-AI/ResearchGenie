1Agent vs Chatbot Discovery runs a plan → act → observe → revise loop. The model writes the queries, four sources are searched, the results are screened for relevance, and the writing audit revises any section that fails (discovery/pipeline.py, writing/graph.py). It asks one clarifying question when a question is vague (#14), and searches again with new queries when too few papers are on topic (#15). The agent adapts only when the evidence says so. Both triggers (a vague question, a thin corpus) are deterministic checks, so its behaviour can be explained and tested. test_clarify.py, test_discovery_replan.py; the live runs Built Live: shown
2Tool-Using Agent Four scholarly APIs used as tools, all through one gateway with per-host pacing, credit-aware retry and a circuit breaker (#3). With native tool calling, the model picks the databases and a query for each. Each call is validated, with a fallback by field (#16). A budget check estimates a run's OpenAlex credits before it starts, and batches DOI lookups at 100 per request (#7). The model chooses the tools, but code checks each choice against the field (no PubMed for mechanical engineering). The gateway knows each provider's credits, so the agent stops before a run would fail, not after. test_scholarly_gateway.py, test_discovery_source_plan.py, the budget-check tests; spike.json Built Live: failed
3Skill Creation Each capability is a reusable unit: Pydantic contracts (shared/contracts/) and 13 prompt files. A headless JSON CLI (run / status / result / resume / doctor) has fixed command lines and exit codes (#10). One Agent Skills folder, skills/researchgenie/, uses only that CLI (#21). One skill runs in two agent runtimes (Claude Code and OpenClaw). It calls only allowlistable command lines: no inline code, no pipe-to-shell. A test fails if the skill and the CLI drift apart. test_headless.py, test_agent_skill.py, agent-skill.md Built
4Memory & Retrieval Short-term memory: the LangGraph state, with SQLite checkpoints. Long-term memory: a research library in SQLite FTS5 that stores every run and paper (#18), and a response cache (#6). Discovery now reads the library: it reuses stored Discussion excerpts by DOI and seeds matching past papers into the candidate pool (#19). --no-memory turns this off. Memory makes later runs faster but cannot get past the safety screen. Seeded past papers still go through the relevance gate, and a test shows an off-topic one is rejected. test_library.py, test_response_cache.py, the library-read tests; the related-run timing in LIVE_PASS.md Built Live: shown
5MCP Connector One model connector (llm_provider.py: Ollama or Gemini). Verification uses the same scholarly gateway as Discovery (#4). researchgenie-mcp is a real read-only MCP server on the official SDK, with six tools: list runs, read an artifact, search the library, summarize a run, search the literature, verify a DOI (#20). Any MCP client (Claude Desktop, Claude Code, OpenClaw) can use our library and DOI checker. The server is read-only by design and refuses path traversal. The DOI tool reports "not found"; it never repairs a reference. test_mcp_server.py (a real MCP client session); mcp-server.md Built
6OpenClaw Runtime Our orchestrator runtime has standard progress events, FastAPI + SSE and the web UI. A durable event log per run (events.jsonl) keeps history across a restart (#8). OpenClaw runs ResearchGenie through the skill: a question from a chat app starts a background run, and OpenClaw sends a message with the decision brief when it finishes (#21). The same run can be watched from a terminal, a browser or a chat app, because every surface reads one event ledger. test_pipeline.py, test_api.py; the chat recording (see agent-skill.md) Built Chat recording: pending
7Agentic Node Graph Research Writing is a 9-node LangGraph with conditional edges and SQLite checkpoints. The Dev Agent is a second graph: plan → failing test → patch → test, at most 3 rounds (#25). Two cooperating graphs: one writes the paper, and the other changes the product's own code under test. writing/graph.py, test_dev_agent.py Built Live: shown
8Parallel Swarm A Send() fan-out with one literature-card worker per paper; parallel source search and full-text fetch; the Trend Advisor's gap-mining swarm, with a merge that needs several papers to agree. A gap counts only when several independent papers raise it (a recurrence threshold), so one paper's wish list does not become a "gap". A barrier test proves that the workers run in parallel. test_trend_gap_mining.py; the advisor runs in LIVE_PASS.md Built Live: shown
9Deep Research Agent Multi-hop research: search, a relevance gate, full-text Discussion mining, future-work candidates checked against a fresh search, gap analysis, then a cited draft. Every run writes an evidence table (#11) and a decision brief (#12). Every claim traces to a row: paper → evidence point → section → DOI → verification status. The brief lists which references to check by hand and gives exactly one next action, without an LLM call. 11 earlier runs in docs/research-papers/; the fresh runs in docs/evidence/live-pass/runs/; test_evidence_table.py, the decision-brief tests Built Live: shown
10Cloud Ops Agent CI on every push (#2). A container image with a local (Ollama) and a cloud (Gemini) profile (#23). The Doctor reads a failed run's log and the live system status, names the cause from a rule table, and applies the fix after confirmation: start Ollama, download the model, add a key, wait for the reset, or resume (#13). The budget check prevents credit failures (#7). Hosted demo: hosted-demo.md (#24). A self-healing ops agent with no guessing. The diagnosis quotes its evidence, a human confirms the fix, and the run resumes from the failed stage instead of starting again. .github/workflows/test.yml, Dockerfile, test_doctor.py (one test per rule); the Doctor live test Built Live: failed
11Agentic SDLC Factory The Dev Agent turns a ticket into tested code. It plans, writes a failing test, then patches with search/replace edits until the test passes. The existing tests run as guards. It works in a throwaway git worktree and never commits; a human applies the diff (#25, #26). Its demo ticket is a real feature: APA 7 citations. The agent shipped a product feature. Red is required first; a "green" with no red is rejected as not_red. The audit trail records every round. test_dev_agent.py; 26-apa-7.md (Result line); docs/evidence/live-pass/devagent/ Built Live: failed
12Safety & Governance Approval gates in the CLI and the web UI. Paper approval before writing (#17). Deterministic QA, and a DOI checker that never repairs a reference. Rollback: a run resumes from the failed stage, and the earlier output is kept as final_v1/, final_v2/ (#9). The Doctor's confirmation rule. Keys are never logged. A governance document maps 6 risks to their control, test and rollback (#22). The output is judged by a checker that is independent of the model that wrote it. Nothing is overwritten: every version stays and can be compared. test_resume.py, test_discovery_approval.py, GOVERNANCE.md Built
13Discipline-Specific The Trend & Gap Advisor ranks rising topics in 6 engineering fields from real OpenAlex counts. The search adapts to the field: engineering and cloud requests skip PubMed (#16). A confirmed pick goes into the full pipeline under one run id (D-040). The topic ranking comes from measured publication growth, not the model's opinion. The model is used only to read the stated future work of real papers. 8 saved advisor runs in 6 fields; the advisor rows in LIVE_PASS.md Built Live: shown
14Capstone Studio One installable system with four entry points (researchgenie, -advise, -dev, -mcp), an HTTP API, a web workbench (resume, paper approval, Doctor, evidence and decision brief), the agent skill and a container. demo-runbook.md has the 12-minute demo. The whole agentic system runs on an 8 GB laptop GPU, with no cloud cost and no data leaving the machine. Gemini is one setting away. the full test count in LIVE_PASS.md; CI; README Built Live: failed
